# transcendence

---
## 프로젝트 개요

이 프로젝트는 SPA(Single Page Application) 구조를 이용해 간단한 웹 애플리케이션을 구현하는 것을 목표로 합니다. 프론트엔드는 TypeScript를 사용하며, 백엔드는 Django를 기반으로 구축되었습니다. 이 문서는 프로젝트를 실행하고, 구조를 이해하는 데 필요한 기본적인 정보를 제공합니다.

## 실행 방법

1. **인증서 생성**
   ```bash
   make certs
   ```
   이 명령어를 통해 SSL 인증서를 생성합니다. `.env` 파일의 `DOMAIN_NAME`에 설정된 도메인 이름을 기반으로 인증서가 생성됩니다.

2. **TypeScript 컴파일**
   ```bash
   tsc
   ```
   이 명령어를 통해 TypeScript 코드를 JavaScript로 컴파일합니다. 컴파일된 파일은 `frontend/dist` 디렉토리에 생성됩니다.

3. **프로덕션 환경에서 애플리케이션 실행**
   ```bash
   make build-prod
   make up-prod
   ```
   이 명령어를 통해 프로덕션 환경에서 Docker 컨테이너를 빌드하고 실행합니다.

4. **애플리케이션 접속**
   `.env` 파일에 설정된 `DOMAIN_NAME`을 브라우저 주소창에 입력하여 애플리케이션에 접속할 수 있습니다.

## 프로젝트 구조

- **backend/**: Django 백엔드 파일이 위치한 디렉토리입니다. API 서버와 데이터베이스 연동을 관리합니다.
- **frontend/**: 프론트엔드 파일이 위치한 디렉토리입니다. TypeScript를 이용하여 SPA를 구현하였습니다.
  - **certs/**: SSL 인증서가 위치한 디렉토리입니다.
  - **nginx/**: Nginx 설정 파일이 위치한 디렉토리입니다.
  - **public/**: 정적 파일(CSS, HTML 등)이 위치한 디렉토리입니다.
  - **src/**: TypeScript 소스 파일들이 위치한 디렉토리입니다.
    - **api/**: 백엔드와의 통신을 관리하는 API 클라이언트 모듈이 위치한 디렉토리입니다.
    - **auth/**: 인증 관련 모듈이 위치한 디렉토리입니다. `AuthProvider`, `AuthService`, `LocalAuthProvider`, `OAuthProvider` 등의 파일이 포함되어 있습니다.
    - **constants.ts**: 프로젝트 내에서 사용하는 상수들을 정의한 파일입니다.
    - **localization/**: 다국어 지원을 위한 모듈이 위치한 디렉토리입니다.
    - **pages/**: 각 페이지 컴포넌트들이 위치한 디렉토리입니다. `MainPage`, `LoginPage`, `SignupPage`, `GamePage` 등의 파일이 포함되어 있습니다.
    - **routes/**: SPA의 라우팅을 관리하는 모듈이 위치한 디렉토리입니다.
    - **userState/**: 전역 상태 관리를 담당하는 모듈이 위치한 디렉토리입니다.
  - **dist/**: TypeScript 컴파일 후 생성된 JavaScript 파일이 위치한 디렉토리입니다.

## SPA 구조 및 모듈화

이 프로젝트는 SPA 구조를 채택하여, 하나의 HTML 파일 내에서 여러 페이지를 동적으로 렌더링합니다. 라우팅, 페이지 전환, 상태 관리는 모듈화하여 관리합니다.

- **라우팅**: `Router.ts` 파일에서 각 페이지에 대한 라우팅을 정의합니다. URL 경로에 따라 해당 페이지의 컴포넌트를 렌더링합니다.
- **페이지 컴포넌트**: 각 페이지는 독립적인 TypeScript 모듈로 구현되어 있으며, 필요에 따라 CSS 파일을 연결하여 개별 스타일을 적용합니다.
- **인증 모듈**: `AuthService`와 `AuthProvider`를 중심으로 로그인 및 인증을 관리합니다. 현재는 임시로 `LocalAuthProvider`를 사용하며, 이후 OAuth2.0 및 JWT 기반의 `OAuthProvider`로 확장할 계획입니다.
- **전역 상태 관리**: `StateManager.ts`를 통해 애플리케이션 전역에서 사용하는 상태를 관리합니다. 로그인 상태, 사용자 정보 등 주요 상태를 효율적으로 관리할 수 있습니다.
- **다국어 지원**: `I18n.ts` 모듈을 통해 다국어 지원을 관리합니다. 다국어 지원은 JSON 파일을 통해 동적으로 로드되며, 사용자의 언어 설정에 따라 자동으로 적용됩니다.
- **CSS 관리**: 전역적으로 적용되는 스타일은 `global.css`에서 관리하며, 페이지별 특화된 스타일은 해당 페이지의 CSS 파일에서 관리합니다.

## 추가 정보

- **확장성**: 프로젝트 구조는 확장성을 염두에 두고 설계되었습니다. 새로운 페이지나 기능을 추가할 때도 일관된 방식으로 쉽게 통합할 수 있습니다.
- **모듈화**: 코드의 재사용성과 유지보수를 고려하여 모듈화를 적극 활용하였습니다. 각 기능은 독립적으로 테스트 및 확장 가능합니다.
- **보안**: HTTPS를 기본으로 하며, JWT 토큰을 사용해 사용자 인증을 관리합니다. 또한, 향후 OAuth2.0 및 2FA(이중 인증) 기능을 추가할 예정입니다.

## 백엔드 : 환경변수 설정
실행 전 backend 디렉토리에 .env 파일을 무조건 만들어야 합니다.

```{env}

EMAIL_HOST_PASSWORD = '(앱 비밀번호)'
```

* 반드시 Gmail 계정을 사용해야 합니다.
* 해당 이메일은 SMTP 설정을 사전에 해놔야 합니다.


## 앞으로의 작업

1. **LocalAuthProvider 업데이트**
   - **JWT와 StateManager를 활용한 로그인 로직 완성**:
     - `LocalAuthProvider`를 사용해 JWT 토큰을 저장하고, 이를 `StateManager`와 연동하여 사용자의 인증 상태를 관리.
     - 추후 OAuthProvider 구현 시, `LocalAuthProvider`를 대체할 수 있도록 구조 유지.

2. **백엔드 연동 구현**
   - **API 엔드포인트 설정 및 연결**:
     - 백엔드에서 정의된 API 엔드포인트(`/api/auth/login`, `/api/auth/signup` 등)와 프론트엔드의 `ApiClient` 모듈을 연동.
     - 실제 로그인, 회원가입, 사용자 정보 조회 등의 기능이 백엔드와 연동되도록 구현.
   - **JWT 토큰 발급 및 검증**:
     - 로그인 시 JWT 토큰을 발급하고, 이를 클라이언트 측에서 저장.
     - API 요청 시 JWT 토큰을 사용해 인증 상태를 확인하고, 필요시 재발급 처리.

3. **프론트엔드 페이지에 Authentication 반영**
   - **로그인 페이지 구현**:
     - 사용자가 이메일과 비밀번호를 입력해 로그인할 수 있는 페이지 구현.
     - 로그인 성공 시 JWT 토큰을 저장하고, 사용자의 인증 상태를 갱신.
   - **로그아웃 기능 구현**:
     - 로그아웃 시 JWT 토큰을 삭제하고, 사용자의 인증 상태를 초기화.
   - **인증 상태에 따른 페이지 접근 권한 설정**:
     - 인증되지 않은 사용자는 특정 페이지(예: 게임 페이지)에 접근할 수 없도록 제한.
     - 인증된 사용자만 접근할 수 있는 페이지를 설정하고, 비로그인 상태에서 접근 시 리다이렉트 처리.

4. **UI/UX 작업**
   - **Bootstrap 등 프레임워크를 활용한 페이지 디자인 및 반응형 UI 적용**:
     - Bootstrap을 활용해 기본적인 페이지 레이아웃 및 스타일링 구현.
     - 반응형 UI를 통해 다양한 디바이스에서의 접근성을 향상.
   - **사용자 경험 개선**:
     - 폼 유효성 검사, 에러 메시지 표시 등을 통해 사용자 경험(UX) 향상.
     - 다국어 지원을 위한 I18n 모듈과의 통합.

5. **보안 검토**
   - **SQL Injection 및 XSS에 대한 방어 추가**:
     - 백엔드에서 입력 데이터를 처리할 때, SQL Injection과 XSS를 방어하기 위한 방어 메커니즘 추가.
   - **HTTPS 설정 검토 및 배포 준비**:
     - HTTPS 설정을 검토하고, 모든 통신이 안전하게 이루어지도록 설정.
     - Docker 환경에서 배포 준비를 위해 필요한 설정 점검 및 최종 확인.

## 프론트엔드 모듈

### 1. `StateManager`
- **목적**: 애플리케이션의 중앙 상태 관리를 담당합니다.
- **메소드**:
  - `getState(key)`: 주어진 키에 해당하는 상태 값을 반환합니다.
  - `setState(key, value)`: 주어진 키에 새로운 값으로 상태를 업데이트하고 관찰자에게 알립니다.
  - `subscribe(key, callback)`: 상태 변경을 관찰하고 해당 변경사항에 반응할 콜백 함수를 등록합니다.

### 2. `Router`
- **목적**: URL 경로에 따라 적절한 페이지 컴포넌트를 렌더링합니다.
- **메소드**:
  - `init(app)`: 라우터를 초기화하고 브라우저의 `popstate` 이벤트에 응답하도록 설정합니다.
  - `loadPage(PageComponent)`: 주어진 페이지 컴포넌트를 로드하고 렌더링합니다.

### 3. `ApiClient`
- **목적**: 백엔드 API와의 통신을 담당합니다.
- **메소드**:
  - `get(url)`: GET 요청을 보내고 응답을 받습니다.
  - `post(url, data)`: POST 요청을 보내고 응답을 받습니다.
  - `put(url, data)`: PUT 요청을 보내고 응답을 받습니다.
  - `delete(url)`: DELETE 요청을 보내고 응답을 받습니다.

### 4. `AuthService`
- **목적**: 사용자 인증을 관리합니다.
- **메소드**:
  - `login(email, password)`: 로그인 요청을 보내고 성공 여부를 반환합니다.
  - `logout()`: 로그아웃 처리를 합니다.
  - `isAuthenticated()`: 사용자의 인증 상태를 확인합니다.
  - `getToken()`: 저장된 토큰을 반환합니다.
  - `getUser()`: 저장된 사용자 정보를 반환합니다.

### 5. `I18n`
- **목적**: 다국어 지원을 관리합니다.
- **메소드**:
  - `t(key)`: 주어진 키에 해당하는 번역된 문자열을 반환합니다.
  - `loadTranslations()`: 번역 파일을 로드합니다.
  - `setLocale(locale)`: 현재 로캘을 변경합니다.
